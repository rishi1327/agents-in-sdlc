GitHub Copilot をエージェントモードで使うと、コードベースを調べ、変更を提案し、ファイルを編集し、コマンドを実行するなど、自律的に作業します。自分のマシンでリアルタイムに実行されるため、VS Code の Copilot Chat ではツール呼び出しやファイル編集の状況を確認できます。差分をインラインでレビューし、個々の変更を適用または却下できます。フォローアップのプロンプトで会話を誘導し、エディターを離れずに作業を改善したり拡張したりできます。

この演習では、次の作業を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして適用します。
- セッションの途中でエージェントを誘導し、ハイコントラストに加えてライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson] で使ったアクセシビリティのカスタムエージェントが、ハイコントラストモードを実装しています。作業中、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザーのために、ライトモードの切り替えも追加したいとのことです。最初から新しい会話を始めるのではなく、既存のセッションを誘導して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案した編集を確認できます。各ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使用した Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツール呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインに表示されます。
    - **Keep** を選択して変更を適用します。
    - **Undo** を選択して変更を元に戻し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開き、このセッションでエージェントが変更したすべてのファイルを確認することもできます。

> [!NOTE]
> ツール呼び出しで許可が必要な場合 (たとえば、ターミナルコマンドの実行など)、エージェントは一時停止し、**Allow** を表示します。内容を確認し、問題のないコマンドだけを許可してください。

5. エージェントがハイコントラストモードの実装を完了するまで待ちます。最後に、変更内容の概要が表示されます。

## ライトモードを追加するようエージェントを誘導する

ハイコントラストモードが実装されたら、同じ会話でライトモードの切り替えも追加します。同じチャットセッションを続けると、エージェントは前の作業で使ったコンポーネント、スタイル、ローカルストレージのパターンなどのコンテキストを保持できます。

1. Copilot Chat の入力欄に次のフォローアッププロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは前の作業で加えた変更を調べ、ライトモードの追加を提案します。
3. ハイコントラストモードと同じように、新しい編集を確認して適用または却下します。各差分で **Keep** または **Undo** を使います。
4. エージェントの方向性が希望と異なる場合 (たとえば、トグルのユーザーインターフェイス (UI) を意図しない方法でリファクタリングしようとする場合) は、チャット入力欄の横にある **Stop** ボタンで作業を停止し、明確なフォローアップメッセージを送信します。

> [!TIP]
> 進行中のセッションを誘導すると、最初からやり直すよりも速く調整できます。フォローアップの依頼を使って、変更を求めたり ("CSS を簡潔にしてください。セレクターの重複ではなく CSS 変数を使用してください")、方向を修正したり ("トグルを 3 つに増やさず、既存の設定パネルにライトモードを追加してください")、範囲を広げたり ("両方の切り替えにキーボードショートカットも追加してください") できます。

## 作業セットをレビューする

変更をコミットする前に、エージェントが編集した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティパターン (Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HTML、ローカルストレージを使った設定の保持など) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次の[レッスン][next-lesson]で変更を公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って進行中のセッションを監視して誘導しました。ファイルの編集を適用または却下し、フォローアップの依頼を送信して、コンテキストを維持したまま作業を拡張しました。

このレッスンでは、次の作業を行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を適用または却下しました。
- フォローアップの依頼で進行中のセッションを誘導しました。

次の[レッスン][next-lesson]では、アクセシビリティ機能の作業を pull request として公開し、このラボ全体でローカルカスタムエージェントが作成した変更をレビューします。
